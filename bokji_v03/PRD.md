# 복지나침반 — 공개서비스 제품 요구사항 v0.3

## 목표
대한민국 누구나 로그인 없이 공공·지자체 복지제도 정보를 찾고, 추후 단계별로 공인 기준에 따른 **자격 사전확인**을 받는 무료 웹앱.

## 범위 및 비범위
- 최종 목표: 전국 중앙부처·지자체·공공기관·교육청 복지정보 집계 및 개인별 맞춤 탐색.
- **이번 v0.3:** 공공서비스 API 컬럼을 정규화하여 카탈로그 스냅샷 생성, 클라이언트 검색, 출처·상태 표시, 정기 수집 워크플로 준비.
- **미포함:** 실제 API 요청 성공 검증, 전체 기관 커버리지, 지역 자동 확정, 재산 소득환산, 실수급 판정, 지원금 합산, 회원가입.

## 비기능 요구사항
1. 모든 입력은 클라이언트 메모리에만 유지. 소득/재산·주소를 서버/API로 전송하지 않는다.
2. 서비스 제목·지원대상·선정기준 등 공식 API 텍스트만 가공. 자연어 선정기준을 AI가 임의 규칙으로 바꾸지 않는다.
3. API가 실패하거나 누락·구조 변화 발생 시 기존 스냅샷 유지(단, 운영자가 최신성 확인 필요).
4. 인증키는 빌드 시 GitHub Secrets에만 저장한다. 정적 사이트에는 공개 카탈로그만 배포한다.
5. 카탈로그 항목에는 원문 링크·수정일·판정 검증상태를 표현한다.

## 장래의 자격판정 엔진 v0.4 설계
- 입력 프로필: 가구원별 나이·관계/거주지, 근로·사업·이전소득, 부동산/자동차/보증금/예금/주식/부채 등.
- `ruleSet`: 제도 ID, 버전, 시행시작일·종료일, 법령 출처, 정기 검증일, 각 소득/재산 계산식·공제·자격요건.
- `rule`: `{field, operator, value, appliesFrom, sourceRef}` 형태. 규칙이 없는 조건은 절대로 충족으로 간주하지 않는다.
- 결과: `needs_review`, `meets_checked_conditions`, `fails_checked_conditions` 세 가지. **최종 수급 가능**이라는 표현을 사용하지 않는다.
- 결과 설명: 사용된 입력, 미확인 입력, 평가한 조건, 공식 조항, 기준일, 담당기관 링크.
- 정책 수정 감지: 카탈로그 원문 변경은 자동 감지하되, 판정 규칙 반영에는 운영자 검토·승인이 필수.

## 단계별 출시 게이트
1. 인증키로 실제 전체 수집 검증, 누락 수·중복 수 측정.
2. 전국/지자체 범위 검증 및 행정구역 코드 체계 적용.
3. 사업별 정규 규칙 작성 및 공식 문서 대조·반례 테스트.
4. 실제 사례를 통한 오판율 검증, 취약 사용자 접근성/보안검토.
5. 공개 출시 후 업데이트 실패 경보와 정정 절차 운영.

## 변경 기록
- v0.2 → v0.3: 대표 사업 샘플 중심 UI → 공공서비스 API 기반 JSON 카탈로그 검색·수집기·예약 갱신 워크플로 구조.
- 사용자 입력 서버 비전송 원칙 유지. 실제 인증키 미제공으로 공식 카탈로그는 아직 연동 미완료.
